# Logo 工作台：整体审查与新版设计建议

日期：2026-09-04

状态：本文为改造依据。内部 V1 已于 2026-09-05 完成首版实现、测试与 EXE 验收，详见 [验收记录](./2026-09-05-internal-v1-verification.md)。本文中的后续建议不等于全部已实现。

最新开发顺序（用户确认）：第一版先开发内部使用的本地应用程序；客户 DIY 网页版放在其后。本文作为内部 V1 的设计与改造依据。[网站客户 DIY 方案](./2026-09-04-web-diy-design.md) 保留为后续版本储备，其中“商家预先配置包款，客户选择后上传 Logo”的决定继续有效，但不作为当前 V1 的交付范围。

## 1. 结论与本次范围

业务目标正确：把客户选款、贴片生产、包厂定位连接起来。现有版本的素材处理、交互和尺寸正确性不足，应该重做这三部分。FastAPI、本地文件存储和矢量引擎适配层的基本方向可以保留。

独立应用继续按用户选定的方案 1：Windows EXE，使用者无需安装 Python，Inkscape 单独安装并在首次启动时检测。先把真实素材和交付流程做正确，再打包。

内部 V1 的操作者是商家/设计人员，由其准备包图、标定尺寸、调整定位框、整理 Logo 和制作方案。核心交付顺序为：

1. **Logo 自动整理**：识别背景、尺寸标注和多个图案，提供干净候选和误判恢复，按有效图案边界计算尺寸。
2. **可反复调整的编辑器**：产品框和定位框可选中、移动、拖控制点；Logo 实体实时跟随；支持毫米输入、缩放平移、撤销和方案比较。
3. **正确交付与订单恢复**：干净客户效果图、准确工艺文件、可读定位图；保存、重开和改稿保持尺寸及素材版本一致。
4. **内部应用交付**：验证真实素材工作流后，打包 EXE，提供 Inkscape 检测与数据目录设置。

客户登录、公开包款目录、在线提交审核和服务器部署属于后续网页版本。V1 通过独立的素材处理、几何和导出模块为其保留复用空间；当前采用本地订单存储，不提前建设网站基础设施。

本次阅读原始设计、架构、交接、交付总结及核心代码，检查项目 01、02、demo_sample 的素材和产物，并运行现有 JS 的内存行为探针与 SVG 几何检查。没有启动完整应用或调用当前电脑的 Inkscape 转换，没有改动原程序和订单数据。PDF 检查使用已存在的产物。

## 2. 用户的真实需求

- 输入来自客户/工厂：包的正视图、AI/PDF/SVG 文件，Logo 文件可能包含底色、尺寸标注、多个图案和大量留白。
- 应用应自动处理常见素材问题，让用户选择要用的干净图案，而不是要求先去 Illustrator 整理好。
- Logo 尺寸以实际印刷图案边界为准，不能拿整个画板或带标注的组合边界当 Logo 尺寸。
- 产品框、定位框能再次选中、移动、拖控制点调整；Logo 本体实时跟随拖动和缩放。
- 用户能输入准确宽度与边距，不必用鼠标碰出一个毫米数。
- 给客户的效果图是干净产品图叠加 Logo。编辑框、控制点和生产尺寸线不进入这份输出。
- 给两家工厂的图纸分别解决印刷尺寸与实物定位；二者与客户选定的方案一致。
- 一个订单可以关掉再打开，可以比较方案和继续改稿。

继续保留原约束：本地使用；一个订单一个包型；程序化叠加；原始矢量保留；不重画 Logo；不建立复杂的包型语义规则库。当前先做好单订单，批量业务另议。

## 3. 已确认的问题

### 3.1 素材入口把客户文件等同于可用 Logo

`app/engine/inkscape.py:88` 的处理是整份文件转 SVG，然后按页面生成 PNG；没有图案选择、背景筛选、标注筛选或有效边界识别。

实际样本：

- `projects/01/input/logo.svg` 的页面为约 557.82 × 529.13 用户单位，包含覆盖整页的矩形路径 `path93`。预览包含黑底、5cm/5.2cm 标注和角色，选款 PNG 也把这整个组合贴上了包。
- `projects/02/input/logo.svg` 的页面约 793.70 × 1122.52，包含全页背景路径 `path89`，并有可读取的 `4.8cm / 5cm / 1.2cm` 文字。当前比例来自整页，真正角色仅占页面局部。
- 01 没有 `<text>` 元素，标注已转为路径；“删除所有 text”无法处理它。反过来，Logo 的品牌文字也不能一律删除。

这是一项缺失的产品能力，不是单纯的上传按钮问题。更换前端框架不会补上它。

### 3.2 工艺图存在实际几何错误，原验证没有覆盖

`app/services/spec_svg.py:125` 把目标宽度额外乘以 `96/25.4`，同时外层 SVG 已将用户单位映射为毫米。已有 viewBox 的分支因此重复应用了尺度因子。

直接调用现有生成函数检查 demo 源：

| 项目 | 正确目标 | 当前结果 |
|---|---:|---:|
| 100 单位宽的原画板映射到 75.3mm | 缩放 0.753 | 缩放 2.846 |
| 原 40 单位宽红矩形 | 30.12mm | 113.84mm |
| 映射后整个原画板宽度 | 75.3mm | 284.6mm |

既有 `projects/demo_sample/output/spec_A.pdf` 的页面确实是 122.3 × 81mm，但红块超出尺寸框并被页面裁切，文字图案没有正确落入页面。`projects/01/output/spec.pdf` 也出现放大的黑底覆盖页面、图案被裁切。

原 `_probe/probe_verify_b89.py` 验证的是标签字符串和 PDF MediaBox；`test_no_recompute.py` 验证特定标识符有没有出现。它们不能证明 Logo 图形尺寸正确，也不能证明实际打印结果正确。

### 3.3 像素和毫米双存，但没有统一维护机制

`web/js/steps/calib_product.js:104` 改标定只更新 calibration，不调整或标记已有方案失效。

在内存中执行现有代码：把标定从 3px/mm 改成 1.5px/mm，方案仍保存 150px、50mm。画面按新标定代表 100mm，记录却仍是 50mm。导出读同一个旧数值，并不能解决矛盾。

`web/js/schemes.js:75` 的 state 通知还会触发 `place.js` 自动初始化和保存，然后外层再提交初始化前的项目。探针记录到保存请求顺序为 `100mm → 0mm`，而屏幕状态是 100mm。这证明存在陈旧保存请求；实际落盘先后还受请求调度影响。

### 3.4 编辑器缺少基础编辑行为

- `web/js/canvas.js:109` 在拖动时仍绘制原位置 Logo，`:114` 只绘制移动中的临时边框。探针确认图案仍在 (100,100)，移动边框已在 (140,130)。
- 产品框和定位框的工具只有新画矩形，没有已有框命中、移动和控制点编辑。
- 没有画布缩放/平移、撤销/重做和键盘微调。
- `web/js/steps/place.js:24` 的宽、高、左右距离是只读 div。
- 底部方案只有编号和尺寸，没有效果缩略图；新方案总绑定 `frames[0]`。
- 后端能加载项目，但前端只有创建入口，没有打开历史订单的操作。

这些缺项直接增加操作次数，也让微调难以预测。

### 3.5 客户效果图与生产图的边界不清晰

核对代码后，需要区分几类内容：

1. 当前选款 PNG 的合成函数没有主动画产品框/定位框，但会原样带入包图自带的标注、Logo 文件中的背景和尺寸线，还会增加方案徽章和页脚文字。
2. 定位图按设计会画框和尺寸线；它不应被当作干净客户效果图。
3. 画布上的控制点和编辑框只应属于编辑辅助层，不能作为客户效果图的截图输出。

因此不能把所有污染都归结为一个“隐藏框”开关。新版要同时处理素材净化、编辑辅助层隔离和清晰的导出种类。

现有 `projects/01/output/placement.pdf` 的尺寸文字明显过小。原因是 `dimension.py` 的 4 单位文字在工艺图中代表 4mm，在定位图的像素坐标中却只有约 1.06mm。标注排版必须按输出纸张统一设计。定位图可以是示意比例，但应明确“按标注尺寸施工”；不能承诺整张产品照片 1:1。

### 3.6 改稿、换素材和输出版本缺少闭环

- 上传同名素材后 URL 不变，`main.js:158/180` 的 URL 比较可能阻止重新加载；上传新源也未立即使旧转换结果失效。
- 客户比较多方案与选定后生产共用同一导出范围，默认只出当前方案，不贴合先比较再确认的业务顺序。
- 绿色“已导出”只记录方案 ID，不绑定版本；修改方案后仍可能显示旧标记。
- 输出采用固定文件名，缺少选定方案快照与改稿版本；SVG 定位图还依赖 `../input/` 的外部底图，单独传文件不自包含。

这些应纳入新版的一个保存和导出流程，不必为此引入云服务或复杂数据库。

## 4. 应保留与应修正的设计判断

### 保留

- 直接操作原矢量、程序化合成；这适合尺寸和颜色可追溯的工作。
- 本地应用、按订单存储文件、JSON 原子写入；数据量与使用方式适合。
- 引擎接口隔离；Inkscape 可继续负责转换与渲染。
- 通用手工定位，不维护庞大的包型枚举。

### 修正

- “三份标签一致”改为“同一方案版本的图形、参数、素材一致”。
- “禁止换算”改为“换算集中在统一几何模块，结果可核验”。正常的坐标转换必须存在。
- “用整个文件宽高”改为“使用选定图案的有效印刷边界”。边界要考虑描边、变换和裁剪，不包含背景和说明文字。
- “同一个矩形同时是安全区和尺寸基准”拆开理解。实物可量的边是定位基准，避让留白是放置约束；默认仍可用一个可编辑矩形快速建立，留白独立设置。
- “照片标定即物理准确”改为“在照片近似正视、对应宽度可靠的前提下估计显示比例”。计算一致不等于实物测量无误；制造容差要由实物样单验证。

## 5. 自动整理 Logo 的建议方案

### 5.1 用户看到的流程

拖入文件后自动处理，显示原稿和“可用 Logo”候选缩略图。规则明确的背景、标注和画板留白默认隐藏。多个图案拆成候选，用户点选要用的一项；可勾选多项合并为一个组合 Logo。

候选图案展示透明棋盘背景、实际选中边界和清理摘要，例如“已隐藏页面背景、尺寸线；识别到 3 个图案”。如自动选择已正确，直接使用；无需手工拆文件。

误判可用“恢复此元素”“排除此元素”“合并为一个 Logo”调整，不编辑原源文件。这里只做对象选择与净化，不做完整矢量绘图软件。

### 5.2 自动化机制

1. 读取页面、图层、组合、路径、文本、裁剪关系和变换，建立对象清单。
2. 找页面范围的大面积底层形状作为背景候选，包括用 path 表达的矩形；结合位置、面积、覆盖关系判断，不按黑/白颜色一刀切。
3. 用 `mm/cm` 文本、尺寸线、箭头、延长线的相互位置识别标注组。已转曲的标注需要几何模式判断，无法简单靠文本匹配。
4. 优先利用源文件的分组与图层，再结合空间关系形成图案候选。图标和品牌字样可能是一个 Logo，不能只按连通区域拆分。
5. 筛选完成后重新计算图案有效边界，规范化为独立矢量资产，并从这份资产生成预览。预览与工艺输出使用同一份清理结果。

现有样本适合先验证：01 的全页背景与 02 的文本标注提供清楚规则；01 的转曲标注则用于检验候选与恢复机制。多个 Logo 尚缺真实多图案样本，首版用合成样本验证分组，再用真实客户文件检查，不能宣称已覆盖全部情况。

Inkscape 官方提供对象几何查询与按对象导出能力，可作为实现基础；具体转换与提取路径仍应在目标版本实测。不能只裁 PNG 预览，而让 PDF 继续使用未清理原稿。

### 5.3 自动化的边界

背景可能本来就是徽章，文字也可能是品牌名称，角色旁的小图形可能属于完整组合。高置信度内容自动处理；歧义集中到候选选择里，不要求用户重回 Illustrator 整理。

若源素材已经栅格化，矢量对象筛选不能恢复原始路径。应单独标明“位图素材”，不能把去背景后的 PNG 冒充可编辑矢量。

产品照片里已经烘焙进去的尺寸标注也与 Logo 文件的矢量标注不同：位于产品外部时可裁切；覆盖产品本体时需要更干净原图或独立图像修复步骤，不纳入本轮自动 Logo 净化的保证。

## 6. 新版工作台交互

### 6.1 首页与素材准备

首页提供最近订单、打开订单、新建订单。新建后直接拖入包图和客户文件，自动转换并准备 Logo 候选，不要求用户点击“转换为 logo.svg”。

### 6.2 同一个工作画布完成标定和摆放

- 左侧：素材、Logo 候选，以及可折叠的产品/定位设置。
- 中间：大画布，滚轮缩放、空格拖动视图；适合画布和 100% 视图入口。
- 右侧：随选中对象变化的属性，直接编辑毫米尺寸、距基准边距离、居中/对齐和留白。
- 底部：真正的方案缩略图，支持新建、复制、删除、比较。

标定默认用产品宽度，允许直接输入 `22.5 cm` 或 `225 mm`，界面统一显示换算值。保持熟悉的产品框方式，并可用左右端点确定已知宽度，避免为一条宽度重复精调四条边。

产品框、定位框：单击选中，拖内部移动，拖边/角控制点调整，Esc 取消本次操作，撤销恢复。操作柄按屏幕像素保持可点击大小。

Logo：拖动时实体实时跟随；锁定比例缩放；宽度输入 50mm 后高度自动推导；键盘按明确步长微调。暂不加入任意变形、透视网格或绘画工具。

“干净预览”临时隐藏全部编辑辅助层。该预览应与客户 PNG 的内容一致，而不是编辑器截图。

### 6.3 确认与交付

客户阶段先导出单张纯净效果图，必要时另出多方案对比图；编号只在对比卡片上展示，不压在产品上。

客户确认某方案后，记录确认的方案版本。工厂交付读取该版本；后续改稿建立新版本，旧确认文件仍可找到。

## 7. 三类输出的明确约定

| 输出 | 默认内容 | 明确不包含 |
|---|---|---|
| 客户纯净效果 PNG | 产品图片 + 选定干净 Logo | 编辑框、控制点、测量线、从 Logo 源带入的说明文字 |
| 工艺 PDF / SVG | 独立干净矢量、1:1 尺寸及色号信息 | 产品照片、客户文件的原画板背景和原尺寸标注 |
| 定位 PDF / SVG | 产品 + Logo、实物基准名称、准确边距与尺寸 | 编辑控制点；不声明产品照片按 1:1 打印 |

工艺文件建议将“尺寸说明”和“1:1 纯图案”分成两页，避免尺寸线被当成印刷内容。SVG 提供干净图案及必要的说明版本，不在一个文件里让工厂猜哪些应印。

输出预览必须针对即将交付的实际文件。定位图统一采用适合阅读的纸张/字号；SVG 嵌入依赖图像。按项目、方案、版本命名输出，并保存素材与参数摘要。

## 8. 尺寸、状态与保存模型

建议用毫米方案作为权威数据，像素作为显示结果或带版本的缓存：

- SourceDocument：不可变的源文件、内容哈希、页面信息。
- LogoAsset：所选原始对象、隐藏对象、清理版本、有效边界、规范化 SVG/PNG。
- ProductView：底图、对应宽度、图像标定及标定版本。
- Placement：LogoAsset 引用、实际宽高、定位基准引用、毫米偏移、色号。
- ExportSnapshot：确认的方案版本、素材版本、标定版本及输出清单。

用户拖动时即时预览；交互结束由统一几何规则提交一次；后端验证并按版本串行保存，屏幕显示保存状态。导出等待该版本保存完成。避免订阅渲染函数再触发业务保存。

修改标定默认保留已设定的物理尺寸，重新计算画面投影；如选择保持当前画面占比，则明确生成重新计算尺寸的新草稿。已确认生产方案不被静默改写。

保存可以继续使用 JSON，但需要版本字段、唯一临时文件和顺序控制。导出转换也在新的任务目录执行，验证成功再发布，避免旧文件被当成新转换成功。

## 9. 技术方案比较

| 方向 | 收益与代价 | 判断 |
|---|---|---|
| 保留本地后端/引擎，重做素材处理、几何与编辑器 | 能满足独立 EXE 和真实工作流；需要集中重构核心 | 推荐 |
| 在旧四步 UI 上逐项修补 | 可修局部问题，但补素材管理、版本和状态后改动会贯穿全局 | 仅适合紧急止血，不作为新版主路线 |
| Illustrator 脚本/面板 | 可利用 Illustrator 的原生文件与编辑能力；运行仍依赖 Illustrator 安装/许可 | 若长期由有 Illustrator 的设计师独用，可作为备选 |

Adobe 官方支持脚本和插件自动化，但这不等于已验证当前文件能无损自动清理。也不应仅因引擎保真问题就把所有用户绑定到 Illustrator。

前端问题不是“用了 Canvas 就不行”。可以重写 Canvas 交互，也可以用图片底层加 SVG 对象与辅助层。就当前对象数量少、框选调整多的需求，我倾向 SVG 图层编辑方式，业务状态采用明确命令更新；是否引入 React/Vue 是次级工程选择，原文“Canvas 用不到 DOM diff，所以不需要框架”的论证不足以决定整个应用架构。

## 10. 建议实施顺序与验收

1. **素材净化和正确尺寸**：先用 01、02 提取可用角色，去除背景/标注；补多 Logo 样本；验证矢量边界与 PNG/PDF 使用同一资产。
2. **可实际操作的编辑器**：框可移动缩放、Logo 实时拖动、毫米输入、缩放平移、撤销、方案缩略图和历史打开。
3. **按用途导出与保存闭环**：纯净客户图、确认快照、工艺/定位输出、改稿版本、异常保存状态。
4. **独立应用包装**：按方案 1 生成 EXE、首次检测 Inkscape、允许选数据目录、程序资源与订单数据分离。

不以“文件成功生成”作为完成条件。至少检查：

- 导入带背景、文本标注、转曲标注、多 Logo、裁剪蒙版的素材时，候选正确且原矢量不损坏。
- 50mm 的测试图形在最终 PDF 中几何边界就是 50mm，检查图形本身而不只检查纸张。打印验证使用实际尺寸/100% 设置。
- 改标定、换同名素材、复制方案、关闭重开、快速连续改数值，屏幕和导出属于同一版本。
- 客户 PNG 不含编辑框/控制点/源 Logo 的尺寸标注；与干净预览一致。
- 真实定位图字号可读，包厂能在实物找到基准，尺寸容差由真实样单确认。

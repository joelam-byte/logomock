## TL;DR

**包类定制 logo 工作台 v1 核心功能全部完成并验证通过。** 上传包图 + 客户 logo → 标定 → 摆放 → 一键导出三份同源交付物（客户选款图 PNG / 工艺尺寸图 PDF / 定位图 PDF），把原本 1 小时+ 的手工排方案压到 5～10 分钟。

## 一、交付了什么

| 模块 | 内容 |
|------|------|
| 后端 FastAPI | 项目管理、文件上传、logo 格式转换、导出编排、引擎适配层 |
| 前端原生 JS | 四步流程（上传/标定/摆放/导出）、Canvas 交互、强制分层 |
| 矢量引擎 | Inkscape 1.4.4 适配层（能力表 + 降级链 + 转曲） |
| 三份交付物 | 选款图（拼版+徽章）、工艺尺寸图（1:1+尺寸链+色号）、定位图（位置尺寸链） |

**核心价值兑现**：三份交付物**同源**——客户在方案上画个圈选定，后两份的毫米数即锁定，无人工二次换算。已通过 T2 同源性测试 + 零换算 grep 断言双重保证。

## 三、关键技术决策（含依据）

| 决策 | 结论 | 依据 |
|------|------|------|
| 前端技术栈 | 原生 JS + 强制分层（state.js/canvas.js） | 界面主体是 Canvas 非 DOM，框架 diff 无效；分层为可迁移 |
| 预览方式 | 前端 Canvas（后端 Pillow 仅导出） | 实测 PNG 编码 133ms，后端预览仅 7.5fps |
| 输出格式 | PDF 主 + SVG，砍 EPS | PDF 印前国际标准；EPS 自身无法自检且 BoundingBox 语义不符 |
| `.ai` 输出 | 放弃 | Inkscape 1.4.4 不支持，专有格式无规范 |
| 存储 | JSON + 原子写入 | 数据量小、人可读可编辑、封装可迁移 |
| 标定 | 2A 产品框（宽度定标）+ 2B logo 框 | Joe 拍板，软包宽度可信、高度不可信 |

## 四、实测发现的重要坑（已写入探测报告）

1. **Inkscape 失败时退出码恒为 0** —— 必须用产物文件判成败
2. **`--help` 格式列表与实际允许值不符** —— 能力探测只能实测
3. **`--export-filename` 扩展名决定输出格式** —— 临时文件须保留目标扩展名
4. **PDF 的 CreationDate 在压缩流里** —— 硬比字节必误报
5. **SVG(mm) → PDF 尺寸 1:1** —— viewBox 数值=mm，偏差 3 纳米

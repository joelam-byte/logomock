# LogoMock 内部应用工作流重设计

日期：2026-09-05  
状态：待用户书面复核  
目标版本：内部业务员日常使用版

## 1. 背景与目标

LogoMock 用于业务员接到定制订单后，把客户 Logo 放到产品图片上，生成一张供客户确认的效果图。客户通常不会实时反馈；业务员需要稍后重新打开任务，基于此前发送的版本继续调整 Logo 的尺寸、位置或颜色，并再次输出。

现有程序已经具备本地项目、毫米标定、Logo 放置、原子保存和导出快照等基础能力，但存在以下主要问题：

- Logo 源文件可能包含背景、尺寸标注、多个 Logo 或多个页面，现有清理流程不够直观；
- PDF/AI 默认只处理第一页，无法满足“源文件是黑盒，所有内容都需要呈现”的业务要求；
- 对象级选择工具和层级命令过于复杂，业务员不应理解矢量文档结构才能完成工作；
- 编辑框不能像常见设计工具一样持续选中、移动和通过控制点调整；
- 导出内容过多，业务员真正需要的是一张可直接发给客户的确认图；
- 导出快照虽然已经存在于文件系统中，但没有形成业务员可查看、恢复和删除的版本存档。

本次重设计的目标是缩短首次学习时间，建立稳定的日常操作记忆，并让“任务—客户反馈—修改—再次导出”的循环可以跨应用重启可靠延续。

## 2. 用户与核心使用场景

主要使用者是公司内部业务员，几乎每天使用。典型场景如下：

1. 新建一个客户任务；
2. 上传一张产品图和一个客户 Logo 源文件；
3. 从 Logo 源文件的全部页面中选择真正需要的内容，排除背景和标注；
4. 按现有程序的方法完成产品尺寸标定；
5. 在产品图上调整一个 Logo 的位置、实际尺寸和显示颜色；
6. 导出一张客户确认图，同时自动形成第一版存档；
7. 退出软件，等待客户反馈；
8. 再次打开任务，选择此前版本并恢复为当前草稿；
9. 按反馈修改并导出，形成下一版；
10. 重复直到客户确认，必要时删除无用的内部版本。

一个任务通常只有一个产品图和一个 Logo 放置。源文件可以包含多个候选 Logo，但业务员勾选后会将它们合成为本任务使用的一份干净 Logo。

## 3. 已确认的产品原则

### 3.1 固定三栏骨架

所有核心工作页保持同一三栏结构：

- 左栏：产品图、Logo、页面或版本等当前任务资源；
- 中栏：候选内容、编辑画布或最终图片预览；
- 右栏：当前选中内容的设置和主操作。

流程切换只替换栏内内容，不改变栏的位置、宽度和基本职责。顶部只保留任务名称、返回、保存和当前阶段唯一的主操作，不使用长篇步骤说明或复杂工具栏。

### 3.2 通过状态自然引导

界面不持续显示大段操作说明。业务员完成当前必要条件后，下一个主操作自然出现：

- 空任务只突出上传产品图；
- 有产品图后突出导入 Logo；
- Logo 尚未确认时进入候选选择；
- Logo 确认后进入标定与放置；
- 数据满足导出条件后启用“生成客户确认图”。

错误说明只在错误实际发生时出现，并直接告诉业务员如何继续。

### 3.3 业务对象而非设计软件术语

界面使用“产品图、Logo、候选内容、实际尺寸、客户确认图、版本”等业务词汇，不把“进入组、节点、图层、路径、框选模式”等矢量编辑命令暴露给业务员。

## 4. 完整工作流设计

### 4.1 任务入口

任务名称保留一个自由文本字段。任务列表提供搜索，并至少显示缩略图、最后更新时间、当前版本数量和简单状态。状态采用业务员可理解的“编辑中、等待反馈、已完成”；系统可以在首次导出后建议切换为“等待反馈”，但最终状态由业务员决定，因为软件无法知道客户是否已经回复或确认。

打开任务后直接恢复当前草稿。草稿在有效修改后自动保存，不要求业务员频繁点击保存按钮。若应用在尚未完成首次导出时退出，重新打开任务仍应恢复最近一次成功保存的草稿。

### 4.2 Logo 导入与全部页面读取

当前重点格式是 PDF 兼容的 AI、PDF 和 SVG。PDF/AI 必须枚举并处理所有可解析页面或画板，不再默认只读第一页。页面按源文件顺序显示；业务员可以逐页查看。

处理要求如下：

- 每个可见页面都必须有预览；
- 每个可见对象必须能在某个候选项中被看到，系统不得静默丢弃；
- 保留源文件本身有意义的组合，例如一个字标中的多个字母默认作为一个候选；
- 背景、尺寸标注和空间上明显独立的其他图形应尽量拆成单独候选；
- 系统只做结构和几何推断，不声称识别出品牌名称或 Logo 语义；
- 候选优先使用原始组名；没有名称时使用“页面 1、组 1、对象 1”等通用名称；
- 业务员可以勾选一个或多个候选，右侧即时显示合并后的透明预览；
- 点击“确认使用”后生成规范化 Logo，但原始源文件始终保留。

源文件中的组不是绝对不可拆分边界。处理器以原始层级作为优先分组依据，同时允许把嵌套组中的大背景、尺寸线和空间上独立内容提升为单独候选。任何自动排除都只是默认建议，必须可以恢复。

如果文档声明的页面数与成功解析页数不一致，界面必须显示失败页面，不能假装已经完整读取。业务员可以看到已成功解析的页面，但在继续前必须明确获知“文件内容没有全部读取”。非 PDF 兼容的旧版 AI 无法可靠解析时，应提示客户重新保存为“PDF 兼容 AI”、PDF 或 SVG；应用不依赖 Adobe Illustrator。

图片格式 Logo 的高级背景去除、像素分辨率判断、自动矢量化和多 Logo 识别不属于本次验收范围。现有透明 PNG 或现有的有限位图导入能力可以保留，但不得宣传为准确的自动清理。该能力列入后续版本。

### 4.3 产品尺寸标定

产品图标定完全沿用现有程序的业务逻辑和毫米换算方法，不重新设计计算模型：

- 在产品图上建立产品尺寸框；
- 输入真实宽度，使用毫米作为标准单位；
- 建立印标参照框；
- 修改产品比例尺后，Logo 的毫米尺寸保持不变，仅重新计算画面像素。

本次只将这些操作放入固定三栏骨架，并减少无关说明，不改变既有标定规则。

### 4.4 Logo 放置与颜色

Logo 在画布上保持可再次选中和调整：

- 拖动 Logo 本体移动位置；
- 四角控制点按原始比例缩放；
- 边中控制点用于单方向调整；
- 右栏可以直接输入宽和高的毫米值；
- 默认锁定原始比例；
- 提供水平居中和垂直居中等少量高频对齐操作；
- 保留撤销和重做。

当前版本提供“原色、黑色、白色、深灰”四种显示方式，不自动判断 Logo 与包身颜色是否接近，也不弹出颜色搭配建议。业务员根据经验选择。原色适合固定配色的 IP 形象或与包身反差合适的品牌 Logo；黑白灰用于需要提高对比度的情况。

颜色调整属于当前编辑方案和版本快照，不覆盖原始 Logo。黑白灰模式统一替换可见填充与描边颜色，同时保留透明度、蒙版和几何结构。潘通色号和任意自定义颜色不属于本次范围。

### 4.5 客户确认图输出

业务员点击“生成客户确认图”后，中栏切换到最终预览，右栏显示简化输出设置，整体仍为三栏。

一次操作只向业务员选定的位置输出一张 PNG 图片。图片包含：

- 产品图片；
- 已放置和着色的 Logo；
- 一行简洁的“Logo 尺寸：宽 × 高 mm”。

图片不包含：

- Logo 选择框和控制点；
- 产品尺寸框、参照框、裁剪框；
- 辅助线、操作提示和方案名称；
- 颜色说明和内部版本号。

输出采用产品原图分辨率；若设置了效果图裁剪范围，则只影响客户确认图。文件名可以在导出前修改。原有 SVG、PDF、定位图、工艺图和 `snapshot.json` 不再作为日常客户输出暴露给业务员；需要保留的项目状态进入软件内部版本存档。

### 4.6 版本存档

版本存档与成功的客户图片导出一一对应：

- 当前编辑状态持续作为“当前草稿”自动保存；
- 只有成功导出客户确认图后才创建正式版本；
- 每个版本保存当时的客户图、完整项目快照、创建时间和简要索引信息；
- 内部按“第 1 版、第 2 版……”显示，删除版本后不重新编号，后续编号不复用；
- 选择版本时，中栏显示当时的客户图，右栏显示当时的 Logo 尺寸、颜色和导出时间；
- “从此版本继续编辑”把快照复制为当前草稿，不修改原版本；
- 再次导出后创建下一版；
- 删除版本需要明确确认，只删除软件内部存档，不追溯删除业务员已经另存或发送的图片。

恢复版本前，如果当前草稿含有尚未自动保存完成的修改，系统必须先完成保存或阻止恢复。恢复操作本身也应原子写入，失败时保持原草稿不变。

## 5. 技术方案

### 5.1 选择

采用在现有 Python、FastAPI、本地 Web UI 和文件式项目存储基础上的增量重构，不改用 Electron/Tauri，也不引入 SQLite。

原因如下：

- 当前 `project.json` 已有修订号、原子写入和冲突检查；
- 当前导出已经为每次操作建立独立目录并保存不可变 `snapshot.json`；
- 文件式存储便于绿色版携带、备份和故障恢复；
- 本地单用户、日常任务规模不需要数据库索引；
- 增量改造可以把精力集中在 Logo 处理、交互和版本体验上。

### 5.2 模块边界

系统拆分为五个业务模块：

1. **TaskStore**：任务创建、列表、状态、当前草稿、自动保存和安全路径；
2. **AssetPipeline**：多页面导入、候选分组、候选预览、选择合并和颜色变体；
3. **Editor**：产品标定、参照框、Logo 几何、拖拽控制点、撤销重做；
4. **VersionStore**：版本编号、清单、不可变快照、恢复和删除；
5. **CustomerExporter**：干净客户图渲染、毫米尺寸文字、外部单文件保存。

模块间通过项目模型和明确的服务接口交换数据。UI 不直接拼接或删除项目路径；所有文件操作由后端在当前任务目录内验证并执行。

### 5.3 数据结构

新版本采用下列目录结构：

```text
projects/
  <task-name>/
    project.json
    input/
      <original-and-derived-assets>
    versions/
      version-0001/
        preview.png
        snapshot.json
        manifest.json
      version-0002/
        preview.png
        snapshot.json
        manifest.json
```

`project.json` 保存当前草稿、任务状态和下一个版本编号。`snapshot.json` 保存可恢复的完整项目状态。`manifest.json` 只保存列表所需的稳定元数据，例如版本 ID、序号、创建时间、Logo 毫米尺寸、颜色模式、预览文件名和源项目修订号。

`versions/` 是应用内部数据，不等于业务员选择的外部导出位置。客户图导出成功后，应用在内部保留一份同内容预览，保证即使业务员移动了外部文件，版本仍可查看和恢复。

现有 `output/export-*` 目录不自动删除。兼容层可以把包含有效 `snapshot.json` 和效果图的旧目录作为“旧版导出”只读展示；第一次从旧快照继续编辑时再按新模型保存。无效或不完整的旧目录不自动迁移。

### 5.4 导出与建档事务

导出过程按以下顺序执行：

1. 校验当前修订、素材和几何数据；
2. 在任务目录的临时文件夹中渲染客户确认图；
3. 验证图片能够重新打开且尺寸正确；
4. 写入临时 `snapshot.json` 和 `manifest.json`；
5. 把客户图写入业务员选择的外部路径；
6. 将临时版本目录原子移动为正式版本目录；
7. 更新 `project.json` 的版本索引和下一个版本编号；
8. 向 UI 返回成功结果。

任何步骤失败都不产生半个正式版本，也不覆盖此前版本。临时目录可以在下次启动时安全清理。外部文件名冲突时必须询问覆盖或更换名称，不能静默覆盖。

## 6. 错误处理

- **未配置 Inkscape**：在导入 AI/PDF/SVG 时直接显示设置入口和可执行文件要求，不让业务员进入空白处理页；
- **非 PDF 兼容 AI**：说明原因并要求重新保存为 PDF 兼容 AI、PDF 或 SVG；
- **部分页面解析失败**：失败页面保留在页面列表并明确标红，不能宣称文件已完整读取；
- **候选结果为空**：保留源页面预览，允许重新分析或更换文件，不生成空 Logo；
- **素材丢失或损坏**：打开任务时指出具体缺失项，不覆盖现有项目数据；
- **自动保存冲突**：沿用项目修订号，提示重新载入，旧窗口不得覆盖新数据；
- **导出失败**：保留当前草稿和既有版本，显示可执行的原因，不创建版本号；
- **恢复失败**：当前草稿保持不变；
- **删除版本**：展示版本号和时间并要求确认，删除范围限制在该任务的指定版本目录。

## 7. 验收标准

### 7.1 Logo 处理

- 一个包含至少两页的 PDF 兼容 AI/PDF 能显示全部页面；
- 第二页上的独立 Logo 可以被选中并确认使用；
- 一个按源文件分组的五字母字标默认只需选择一次；
- 同组或嵌套结构中的背景和尺寸标注能够作为独立候选排除；
- 所有可见源内容均能在页面预览或候选中找到，不发生静默丢失；
- 候选名称不依赖品牌语义识别。

### 7.2 编辑

- 产品尺寸标定结果与现有程序一致；
- Logo 可反复选中、移动和拖动控制点缩放；
- 输入毫米尺寸与画布变化互相同步；
- 原色、黑、白、深灰不会修改原始素材；
- 核心工作页始终保持固定三栏骨架。

### 7.3 输出

- 一次导出只在用户选定位置产生一张 PNG；
- 图片只含产品、Logo 和“宽 × 高 mm”文字；
- 编辑框、控制点、参照框、辅助线和内部版本号均不出现在图片中；
- 导出图片可以正常打开，并采用预期分辨率。

### 7.4 版本

- 每次成功导出创建且只创建一个新版本；
- 退出并重新启动应用后仍能查看版本；
- 恢复第 1 版后，尺寸、位置、颜色和相关素材与当时一致；
- 从旧版修改并导出会创建新版本，不覆盖旧版；
- 删除一个版本不影响当前草稿、其他版本和外部导出文件；
- 模拟写入中断不会留下可见的半成品版本。

## 8. 测试策略

- 后端单元测试覆盖多页面枚举、候选分组、颜色变换、版本编号、快照恢复、安全删除和原子失败；
- API 集成测试覆盖任务保存、导出建档、版本列表、版本恢复、版本删除和修订冲突；
- 前端测试覆盖自然启用流程、候选勾选合并、拖拽与控制点、毫米输入同步、三栏布局状态和无辅助框导出；
- 使用真实或脱敏样例进行人工验收：多页面 PDF 兼容 AI、带背景和尺寸标注的字标、固定配色 IP Logo、黑白灰品牌 Logo；
- 构建绿色版后在未安装 Python 的 Windows 环境验证启动、项目重开和版本恢复；
- 在已安装正式版 Inkscape 的环境验证 AI/PDF/SVG 导入，并验证未配置 Inkscape 时的错误引导。

## 9. 明确不在本次范围内

- 客户自助 DIY 网页端；
- 产品图库、包款颜色变体和历史推荐尺寸；
- 位图 Logo 的高级自动去背景、自动矢量化和像素质量判断；
- 潘通色、自定义任意颜色和颜色接近提示；
- 多个独立 Logo 放置、多面印刷和复杂生产工艺文档；
- 云同步、多人协作、账号系统和在线素材上传；
- SQLite、Electron/Tauri 或新的桌面运行时。

产品图库属于后续版本的高优先级能力；位图智能处理次之。后续能力不得破坏本设计确立的任务、三栏工作区和版本存档模型。

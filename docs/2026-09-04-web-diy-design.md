# 包类 Logo 网站 DIY：产品方案

日期：2026-09-04

状态：后续版本储备，当前暂不开发。用户已明确先开发内部应用 V1，再开发客户 DIY 网页版。产品模板仍由商家预先配置，客户选择后上传 Logo。下文“首版”均指未来网页版的首次交付，不指当前内部应用 V1；网站尚未实现或部署。

前置依据与当前开发主线：[内部应用 V1 审查与改造建议](./2026-09-04-design-review-and-v2-proposal.md)。先在内部应用中解决素材净化、尺寸错误、保存竞态和导出问题，后续网页版复用经过验证的核心能力。

## 1. 产品方向

商家配置可信的产品模板，客户在模板允许的范围内自行设计，提交后由商家审核生产。

首版客户从商家提供的包款中选择。产品照片、真实尺寸、印刷区域、定位基准均由商家维护；客户只操作自己的 Logo 和方案。

开发顺序为内部应用 V1 → 客户 DIY 网页版。内部版按已选方案交付 Windows EXE，Inkscape 单独安装。素材整理、几何与导出核心保持独立，后续迁移到服务器时再增加多人数据隔离、在线存储和任务执行能力。

## 2. 两种使用界面

| 商家后台 | 客户 DIY |
|---|---|
| 新建/维护包款，准备干净产品图 | 浏览包款或打开指定包款链接 |
| 设置真实宽度、标定和实物定位基准 | 上传 Logo 文件 |
| 用可调整的矩形设定可印区、留白与尺寸范围 | 查看清理后的 Logo 候选并选择 |
| 设置默认摆放、发布模板版本 | 拖动、缩放、居中、输入宽度 |
| 查看客户方案与原始文件 | 保存/复制方案、下载干净效果图 |
| 检查生产可用性，确认后导出生产文件 | 提交选定方案及联系信息/备注 |

模板编辑中的产品框和定位框支持选中、移动、控制点调整、撤销。客户端的模板边界锁定，编辑 Logo 时显示可印区提示，干净预览和客户 PNG 中隐藏辅助线。

## 3. 产品模板

首版每个包款配置一个正面视图、一个可印区。多个视图和印刷面在数据关联上可扩展，首版界面先保持单面简单操作。

一个可发布模板包含：

- 包款名称、展示用干净图片。
- 已知实物宽度及对应图像宽度，用来建立显示比例。
- 可印区域与明确的定位基准；基准名称应能对应实物，例如“前袋左边”“翻盖下边”。
- 允许的 Logo 尺寸和安全留白，默认尺寸、默认位置。
- 模板版本与发布状态。

只有上述必要数据有效时才可发布。数值由商家设定，不能从画面观感自动编造生产限制。

模板更新产生新版本；客户已经保存或提交的方案继续引用原版本，避免换照片或修改宽度后旧订单发生漂移。

## 4. 客户的一次完整操作

1. 打开指定包款的链接；也可以从包款列表选择。
2. 上传文件，页面显示处理进度和结果。
3. 系统展示推荐的干净 Logo。多个图案显示候选，客户选择一个；需要保持组合时可合并候选。
4. 进入画布，Logo 按模板默认尺寸和位置放置。
5. 拖动、缩放或输入宽度进行调整；居中和重置提供快捷入口。
6. 保存为方案，可复制后比较不同大小和位置。
7. 下载纯净效果图，或提交当前选定版本。提交成功显示编号和回访入口。

手机端采用大操作柄、清楚的确认按钮和可收起的属性面板；电脑端同时显示画布与尺寸属性。Logo 保持比例，越界时限制位置并解释原因。

首版可按受控分享链接试用：客户编辑会话独立，分享查看与继续编辑的权限分开；后台需要商家登录。客户账户不是首版流程的前置条件，但服务端必须校验会话归属，不能通过修改订单名访问其他客户的数据。

## 5. 自动整理 Logo

继承审查方案中的原始对象分析、背景/标注候选识别和有效边界计算。页面底色、画板留白、原尺寸线不应决定印刷图案的尺寸。

规则明确的情况直接生成清理候选；不确定的文字、底色或组合关系提供保留/恢复选择。客户不必认识图层、path 或 viewBox。

源文件始终保留，清理结果有独立资产版本。画布预览、客户效果图和工艺文件都引用同一份干净资产。

拟支持常见 PNG/JPEG，以及 SVG、PDF、PDF 兼容 AI 文件。位图可以用于预览，但是否适合按目标尺寸生产必须单独检查；不能把它标成原生矢量。无法可靠处理的文件进入商家待处理状态，保存客户意图与原稿。

## 6. 提交与审核

客户提交的是确定版本的设计，不只是截图。后台收到：

- 包款与模板版本。
- 原始 Logo、清理后的资产、所选图案和清理记录。
- 实际宽高、距基准边距离、效果图。
- 客户联系信息、备注、方案版本和提交时间。

商家可以接受、调整或请客户修改。商家若调整尺寸或位置，应形成新版本并让客户查看确认后的效果。

状态建议为“草稿 → 已提交 → 待修改/已确认 → 已导出”。确认针对具体方案版本；改稿不会覆盖原确认记录。

未来网页版首版的业务闭环是提交设计并由商家跟进，报价、支付与物流系统不作为该版本的依赖。

## 7. 输出约定

| 文件 | 用途 | 内容 |
|---|---|---|
| 客户效果 PNG | 客户选择/分享 | 干净产品图与 Logo；无控制点、定位框或测量线 |
| 方案对比 PNG | 可选的方案比较 | 多个独立效果卡片，编号置于产品画面外 |
| 工艺 PDF/SVG | 贴片生产 | 规范化图案、准确物理尺寸；说明与实际印刷图案分开 |
| 定位 PDF/SVG | 包厂定位 | 产品、Logo、可识别的实物基准、可读的毫米标注 |

客户效果由独立的合成过程生成，不截取编辑画布。服务器按提交的权威参数重新生成正式交付，不能仅信任浏览器上传的尺寸文字或截图。

工艺文件应验证真实图形的物理边界，不只验证标签和纸张大小。客户预览照片的准确性仍依赖商家标定质量，生产前保留实物验证环节。

## 8. 共享核心与网站改造

- 编辑界面在客户浏览器中运行，拖动过程本地即时绘制。
- 在线 Python 服务负责模板、设计、提交与审核。
- 文件转换和净化放在独立任务中，服务器运行 Inkscape；客户无需安装任何相关软件。
- 对象存储保存原稿、干净资产和产物；事务数据库保存模板、客户会话、方案版本和审核状态。既有订单 JSON 可作为迁移/归档输入，但不应直接充当公共网站的并发订单存储接口。
- 统一几何模块维护毫米尺寸，保存操作带版本，导出绑定确认快照。
- 文件访问受会话/用户权限控制；上传转换限制资源用量、执行时间及外部引用，客户上传的 SVG 不直接作为可信网页内容执行。

这些改造意味着现有本机服务不能原样公开。具体部署供应商与规格在开发部署阶段选择，本次不创建云资源。

## 9. 首版范围和验证顺序

建议先用少量常用包款验证一个完整闭环：

1. 商家配置模板、发布设计链接。
2. 客户上传含背景/标注的真实 Logo，完成净化候选选择。
3. 客户调整并保存方案，导出干净效果图。
4. 客户提交，商家查看同一版本并确认。
5. 验证工艺和定位文件后，部署受控试用。

目前项目 01、02 可用于内部开发验证素材问题；它们不因本设计文档而成为公开网站的示例素材。真实多 Logo 文件和真实客户试用反馈用于补充分组、操作和生产验收。

判断首版是否成功：客户不用画框标定或离开网站拆分 Logo；能完成一次上传、调整、保存和提交；商家打开后看到相同的尺寸与效果；正式输出无图案缩放错误和编辑辅助线污染。
